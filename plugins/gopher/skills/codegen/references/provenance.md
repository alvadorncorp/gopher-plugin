# Artifact Provenance

Provenance is the record that makes a generated artifact reproducible by someone
who was not there when it was generated. Without it, a difference between the
checked-in output and a fresh run cannot be attributed.

## The provenance record

| Field | Meaning | How it is observed |
|---|---|---|
| `generator` | Module path and package of the producer | `tool` directive in `go.mod`, `tools.go` import, or the directive text |
| `version` | The exact pinned version | `go list -m -f '{{.Path}} {{.Version}}' <module>` |
| `command` | The command as declared, including flags | the `//go:generate` line, Makefile target, or registry config |
| `inputs` | Every file the generator reads | schema files, source types, registry config, templates |
| `input_hashes` | Content hash per input | `git hash-object <file>` or `shasum -a 256 <file>` |
| `toolchain` | Go version and toolchain selector | `go version` and the `go`/`toolchain` lines in `go.mod` |
| `outputs` | Every file the generator writes | the artifact paths |
| `output_hashes` | Content hash per output | `git hash-object <file>` |
| `owner` | The skill or team accountable for the generator | project convention |

Record inputs as a set, not as one file. A generator that reads a template
directory, a registry config, and a package of Go types has three input classes,
and a change in any of them can move the output.

## The code generation header

Go defines one machine-readable marker for generated source. A generated file
carries a line matching this regular expression:

```text
^// Code generated .* DO NOT EDIT\.$
```

The precise requirements are:

- The line matches the expression exactly, including the trailing period after
  `DO NOT EDIT`.
- The line appears before the first non-comment, non-blank text in the file.
- The line names the producer, so a reader can trace the artifact back.

A conventional form names the generator and its invocation:

```go
// Code generated by stringer -type=Pill; DO NOT EDIT.
```

Tools and reviewers rely on this marker to exclude generated code from linting,
review, and coverage expectations. An artifact without it reads as hand-written
source, which is how hand edits enter generated files unnoticed. Treat a missing
header as an adoption item (`references/adopt.md`), not as a hand edit of the
artifact's body.

## Recording a reproducible pin

A pin is reproducible when another machine can obtain the same generator without
guessing. Prefer, in order:

1. A `tool` directive in `go.mod` with a resolved version in `go.sum`, invoked
   as `go tool <name>`.
2. A blank import under `//go:build tools` with a resolved module version.
3. An explicit `go run <module>@<version>` inside the declared command.

Each of these expresses the version in a file the project already reviews. A
generator resolved from `PATH` expresses nothing, so its output cannot be
attributed to a version.

Capture the pin for the record:

```bash
go list -m -f '{{.Path}} {{.Version}}' golang.org/x/tools
go version
grep -n '^go \|^toolchain ' go.mod
```

## When the pin is missing

Report the artifact as unpinned and state the exact pin the project would need,
for example `go get -tool golang.org/x/tools/cmd/stringer@v0.30.0`, and stop
short of installing it. An unpinned generator is a `BLOCKED` reproduction, and
the missing pin is the actionable finding.
